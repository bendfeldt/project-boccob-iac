# postgres-cluster

A CloudNativePG `Cluster` with the platform defaults:

- `instances` = 1 (dev) or 3+ (HA: streaming replication, automated failover,
  required pod anti-affinity, PodDisruptionBudget, optional quorum sync replicas)
- server certificate from the platform PKI, TLS-only `pg_hba`, SCRAM passwords
- data checksums, connection + DDL logging
- optional continuous backup to S3 (RustFS) + daily `ScheduledBackup`
- application credentials generated by the operator and pushed to OpenBao at
  `kv/database/<name>` (`username`, `password`, `dbname`, `port`)

```hcl
module "polaris_db" {
  source    = "../../modules/postgres-cluster"
  name      = "polaris-db"
  namespace = "database"
  image     = module.versions.images["postgresql"].ref
  instances = var.ha ? 3 : 1
  database  = "polaris"
}

module "polaris_db_credentials" {            # in the consumer namespace
  source    = "../../modules/external-secret"
  name      = "polaris-db"
  namespace = module.ns_catalog.name
  kv_path   = module.polaris_db.kv_path
}
# connect to module.polaris_db.host:5432 with sslmode=verify-full and the platform-ca bundle
```

The consumer namespace must be allowed to reach PostgreSQL: add it to
`postgres_client_namespaces` (stack `12-foundation-services`) and add an
egress rule to `database:5432` in its own namespace baseline.

Backups use the in-tree Barman Cloud integration, which needs the `system`
flavour of the operand image (pinned in `versions.yaml`). The Barman Cloud
*plugin* can be wired through `extra_spec` once the ops stack installs it.
